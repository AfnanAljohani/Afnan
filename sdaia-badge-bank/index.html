استراتيجيات النشر

Shadow: النموذج الجديد يستقبل طلبات حقيقية، وردوده ما توصل لأحدمقارنة بدون أي مخاطرة
Canary: نسبة صغيرة من المستخدمين (مثل 5%) تروح للنسخة الجديدةتجربة تدريجية على مستخدمين حقيقيين
Blue-Green: بيئتين كاملتين، وتحولين كل الطلبات مرة وحدةتحويل كامل ورجوع فوري
A/B test: تقسمين المستخدمين بين نسختينقياس أثر تجاري (مبيعات، نقرات)
Batch مقابل Real-timeيومي أو أسبوعي ← Batch · أجزاء من الثانية ← Real-time

المراقبة: ليش الأداء نزل؟

  • Data drift: المدخلات نفسها تغيّرت (مثلًا صار يدخل عملاء أصغر سنًا).
  • Concept drift: المدخلات نفسها، لكن العلاقة بينها وبين النتيجة تغيّرت (المحتالين غيّروا أسلوبهم).
  • Training-serving skew: الأداء سيئ من أول يوم، لأن المعالجة وقت التشغيل تختلف عن وقت التدريب. الحل: نفس الـpipeline أو feature store.
  • Label delay: الإجابات الصحيحة تتأخر أشهر، فتراقبين drift وproxy metrics.

الإصدارات وإعادة الإنتاج

  • Model registry: يحفظ كل نموذج مع رقم إصداره ومقاييسه وحالته.
  • Reproducibility: ثبّتي الـseed وإصدارات المكتبات (أو container) ونسخة البيانات والإعدادات.
  • Rollback bundle: ترجعين النموذج والكود والإعدادات ونسخة البيانات مع بعض، مو النموذج بس.
  • Eval gate: أي إصدار ما ينزل إلا إذا نجح في التقييم (الدقة، العدالة، زمن الاستجابة).
  • Continuous Training: إعادة التدريب تكون بمحفّز (drift، انخفاض أداء، جدول زمني)، مو بشكل عشوائي.

LLMOps

  • Prompt versioning: الـprompt مثل الكود: إصدارات ومراجعة وتقييم وإمكانية رجوع.
  • Eval set ثابت تقيسين عليه الهلوسة والجودة قبل أي تعديل.
  • Guardrails: فلترة المدخلات والمخرجات (بيانات شخصية، prompt injection).
  • معلومات قديمة في نظام RAG ← حدّثي الـindex، مو fine-tuning.
  • تكلفة عالية ← caching، نموذج أصغر للمهام البسيطة، تقليل التوكنز.

الموثوقية

  • SLI = المقياس (نسبة التوفر، p99 latency) · SLO = الهدف (مثل 99.9%).
  • Error budget = (1 − SLO) × المدة. مثال: 99.9% على 30 يوم = 0.001 × 43,200 = 43.2 دقيقة.
  • Burn rate: سرعة استهلاك الـerror budget. إذا عالية ← تنبيه فوري.
  • Fallback / Circuit breaker: إذا تعطل النموذج ارجعي لقاعدة بسيطة أو نسخة أقدم بدل ما تنهار الخدمة.

البيانات: كيف أجهزها وأقسمها، وأختار الخوارزمية، وأقيس النموذج بالمقياس الصح.

جودة البيانات والتسريب

  • Missing values: لو التوزيع منحرف (skewed) استخدمي الوسيط بدل المتوسط.
  • Data leakage: خاصية تحتوي معلومة من المستقبل أو من الهدف نفسه ← احذفيها. علامتها: نتيجة ممتازة بشكل غير منطقي.
  • القاعدة: قسّمي البيانات أولًا، وبعدها اعملي fit للـscaler والـimputer على بيانات التدريب فقط.

تقسيم البيانات

  • سلاسل زمنية (مبيعات، طلب) ← قسمة حسب الوقت: تدريب على الماضي واختبار على المستقبل، بدون shuffle.
  • فئات غير متوازنة ← stratified split.
  • نفس العميل أو المريض له عدة صفوف ← group split / GroupKFold عشان ما يظهر في التدريب والاختبار.

المقاييس

Precision = TP/(TP+FP)لما الإنذار الكاذب (FP) مكلف: إيميل مهم ينحجب كسبام
Recall = TP/(TP+FN)لما تفويت الحالة (FN) مكلف: احتيال، سرطان
F1توازن بين الاثنين
PR-AUCبيانات غير متوازنة جدًا
Accuracyمضللة إذا الفئات غير متوازنة
MAEانحدار، أقل تأثرًا بالقيم الشاذة وسهل التفسير
RMSEانحدار، يعاقب الأخطاء الكبيرة أكثر

Overfitting و Underfitting

  • Overfitting: التدريب عالي والاختبار منخفض ← regularization، نموذج أبسط، بيانات أكثر، early stopping، dropout.
  • Underfitting: الاثنين منخفضين ← نموذج أعقد أو خصائص أفضل.

الخوارزميات

  • KNN: لازم scaling للخصائص. k صغير جدًا ← overfitting.
  • Decision tree: سهل التفسير، يميل للـoverfitting ← max_depth / pruning.
  • Random Forest (bagging): يقلل التباين (variance) · Gradient Boosting / XGBoost: الأقوى غالبًا في البيانات الجدولية.
  • Logistic Regression: خط أساس (baseline) سهل التفسير.
  • K-means: تجميع بدون labels، يحتاج k وscaling · PCA: تقليل الأبعاد.
  • Association rules (سلة المشتريات): support، confidence، lift. إذا lift > 1 فالعلاقة إيجابية.

الشبكات العصبية والنماذج التوليدية: متى أستخدم أي معمارية، وكيف أحل مشاكل التدريب، ومتى RAG ومتى fine-tuning.

أساسيات الشبكات العصبية

  • Activation: ReLU للطبقات المخفية · Sigmoid لمخرج ثنائي · Softmax لعدة فئات.
  • Loss: Binary cross-entropy للثنائي · Categorical cross-entropy لعدة فئات · MSE للانحدار.
  • الـloss يتذبذب أو يصير NaN ← قللي learning rate. التعلم بطيء جدًا ← زيديه.
  • Vanishing gradients ← ReLU، batch normalization، residual connections.

المعماريات

  • CNN: صور · RNN / LSTM: تسلسلات (قديمة نسبيًا) · Transformer: نصوص وتسلسلات بالـattention · ViT: صور بالـTransformer.
  • Transfer learning: بيانات قليلة ← نموذج مدرّب مسبقًا + fine-tune لآخر الطبقات + data augmentation.
  • Autoencoder: كشف الشذوذ بدون labels عن طريق reconstruction error.
  • GAN وDiffusion: توليد صور.

الذكاء الاصطناعي التوليدي

  • Temperature منخفضة ← إجابات ثابتة ودقيقة · عالية ← إبداع وتنوع.
  • Hallucination ← RAG مع مصادر (grounding + citations) + temperature منخفضة.
  • RAG: لما المعرفة تتغير أو خاصة بالشركة · Fine-tuning: لما تبين أسلوب أو صيغة أو سلوك ثابت.
  • LoRA / PEFT وquantization: fine-tuning بموارد GPU قليلة.
  • Embeddings + vector DB: بحث دلالي · استرجاع ضعيف ← حسّني chunking، reranking، hybrid search.
  • Few-shot وchain-of-thought: تحسين الـprompt قبل ما تفكرين في fine-tuning.
  • Agents: أدوات بصلاحيات أقل ما يمكن، وموافقة بشرية على الإجراءات الخطرة.

فئات المخاطر

  • Little or no risk: مثل فلتر السبام. بدون قيود.
  • Limited risk: تطبيق مبادئ الأخلاقيات.
  • High risk: مثل التوظيف أو التشخيص الطبي أو الائتمان. يحتاج تقييم مطابقة قبل وبعد النشر، وإشراف بشري.
  • Unacceptable risk: مثل التصنيف الاجتماعي (social scoring). ممنوع.

نظام حماية البيانات الشخصية PDPL

  • الموافقة وتحديد الغرض: لا تستخدمين البيانات لغرض جديد بدون أساس نظامي أو موافقة.
  • Data minimization: اجمعي الحقول اللي تحتاجينها فقط.
  • حقوق صاحب البيانات: الاطلاع، والتصحيح، والإتلاف.
  • التسريب: إشعار الجهة المختصة (سدايا) خلال 72 ساعة.
  • النقل خارج المملكة له شروط وضوابط.
  • Pseudonymization (يمكن إرجاع الهوية) ≠ Anonymization (ما يمكن إرجاعها).

كيف أبني خدمة الذكاء الاصطناعي ككود سليم: APIs، واختبارات، وتكامل مع الأنظمة، وأسئلة مخرجات الكود.

APIs والتكامل

  • Input validation بمخطط (schema / pydantic) عشان المدخلات الخاطئة ما تطيّح الخدمة.
  • API versioning (/v1, /v2) عشان التغييرات ما تكسر العملاء.
  • 429 Too Many Requests ← retry with exponential backoff.
  • Idempotency key: إعادة المحاولة ما تكرر العملية (مثل دفع مرتين).
  • معالجة طويلة (فيديو، ملفات كبيرة) ← async job + queue + polling / webhook.
  • أحداث لحظية مستمرة ← streaming / message queue (Kafka).

جودة الكود والاختبارات

  • Unit tests لدوال المعالجة · Integration tests للخدمة كاملة · Data validation للبيانات الداخلة.
  • «يشتغل عندي بس» ← Docker + إصدارات مكتبات مثبتة.
  • مفتاح API في الكود ← انقليه لـsecrets manager وغيّري المفتاح (rotate).
  • الإعدادات في ملفات config، مو مكتوبة داخل الكود · logging منظم.

أسئلة مخرجات الكود (Python)

  • scaler.fit(X_test) أو fit_transform على الاختبار ← تسريب.
  • list[::-1] يعكس القائمة · 7 // 2 = 3 · 7 % 2 = 1.
  • def f(x, lst=[]): القائمة الافتراضية تُشارَك بين الاستدعاءات.
  • df.groupby("a")["b"].mean(): متوسط b لكل قيمة a.
  • np.zeros((3,1)) + np.zeros((1,4)) ← شكل (3, 4) (broadcasting).

أين يشتغل النموذج، وبأي تكلفة وسرعة، وكيف يتحمل الضغط.

السرعة والأداء

  • Latency (زمن الطلب الواحد) ≠ Throughput (عدد الطلبات في الثانية). Batching يرفع الـthroughput.
  • تسريع النموذج: quantization (INT8)، pruning، distillation لنموذج أصغر، caching، GPU.
  • p95 / p99: 95% أو 99% من الطلبات أسرع من هذا الرقم.

  1. احذفي أي خيار يكسر قيدًا (مثل p95 < 200ms أو الامتثال).
  2. من الباقي اختاري الأرخص.
  3. التكلفة = عدد الساعات × سعر الساعة × عدد الأجهزة. انتبهي لتحويل الأيام والأشهر (30 يوم = 720 ساعة).

D7 · 6.7%

التفكير كمهندس في شركة: المشكلة التجارية أولًا، والتواصل، والتكلفة والعائد، والتعاون.

قواعد هذا المحور

  • حددي المشكلة والمؤشر (KPI) أولًا قبل اختيار أي نموذج.
  • إذا قاعدة بسيطة تحل المشكلة ← لا تستخدمين ML.
  • قيمة غير مؤكدة وميزانية محدودة ← PoC / pilot / MVP.
  • Build vs Buy: إذا فيه خدمة جاهزة تحقق الحاجة بتكلفة أقل ← اشتريها.
  • التواصل مع غير التقنيين: الأثر التجاري ورسوم بسيطة، بدون مصطلحات.
  • طلبات جديدة في نص المشروع (scope creep) ← إدارة التغيير وترتيب الأولويات مع أصحاب المصلحة.
  • طُلب منك إخفاء ضعف في النموذج ← الشفافية والتصعيد.
  • ROI = (Benefit − Cost) / Cost.

أهم ما قاله المختبرون (24 نوفمبر): الأسئلة طويلة (بعضها أكثر من 16 سطر) ومحوسبة، فيها رسوم بيانية وجداول، وKNN و Model trees، وأكواد تسأل عن سبب المخرج، وحسابات بسيطة، وأسئلة تكاليف وميزانية وحلول تشغيلية للشركات. أكثرهم قالوا إن بنك الـ 140 هو الأقرب لشكل الاختبار. السر: إنجليزي + تركيز + قراءة آخر سطر في السؤال أولاً.

قاعدة الاختبار الذهبية

  1. اقرئي آخر سطر (المطلوب) قبل السيناريو: BEST / FIRST / MOST likely / NOT / Select TWO.
  2. اكتبي في ذهنك القيود: زمن (p95)، ميزانية، دقة/Recall، امتثال، قدرة فريق المراجعة.
  3. استبعدي أي خيار يكسر قيداً واحداً حتى لو كان الأدق أو الأرخص.
  4. بين المتبقي: اختاري ما يعالج السبب الجذري لا العَرَض، وبأقل تكلفة وتعقيد.
  5. الوقت: 120 سؤال في 180 دقيقة = 90 ثانية للسؤال. أكثر من دقيقتين؟ علّميه وارجعي له.
